이슈 제목과 설명을 입력받아 표준화된 GitHub Issue를 생성하는 커맨드입니다.

---

## 사용법

```
/issue [이슈 제목]

[화면 또는 기능 설명]

[세부 요구사항 목록]
```

### 예시

```
/issue Box 화면 및 보관함 기능

사용자가 저장한 곡을 보관하고 탐색할 수 있는 화면

- 정렬기준 : 최근에 저장됨, ㄱㄴㄷ/ABC 오름차순 및 내림차순
- 곡 리스트 (스크롤 가능)
- 제목 검색 기능
- 리스트 타일: 아이콘, 제목, 생성일, 더보기 버튼
```

---

## 실행 절차

### STEP 1 — 입력 파싱

`$ARGUMENTS`에서 아래 정보를 추출한다:

- 이슈 제목: 첫 줄
- 설명: 두 번째 줄 (기능 목적)
- 요구사항 목록: 그 아래 bullet 리스트

---

### STEP 2 — 구조화

입력된 내용을 기반으로 다음과 같이 재구성한다:

- DESCRIPTION → 한 문장으로 명확하게 요약
- TO-DO → 기능 단위로 그룹핑
- ETC → 확장성 및 추가 고려사항 작성

---

### STEP 3 — 이슈 본문 생성

아래 형식으로 Markdown을 생성한다:

```
## DESCRIPTION

> [기능 또는 화면의 목적을 한 문장으로 작성]

## TO-DO

>

- [ ] AppBar 적용 (로고)
- [ ] [핵심 기능 1]
  - [ ] [세부 작업 1]
  - [ ] [세부 작업 2]
- [ ] [핵심 기능 2]
  - [ ] [세부 작업 1]
  - [ ] [세부 작업 2]

## ETC

> [확장성, 이후 연결 기능, 고려사항]
```

---

### STEP 4 — 메타 정보 확인

생성된 이슈 본문을 사용자에게 보여준 뒤, 아래 항목을 **한 번에** 질문한다:

```
다음 정보를 입력해 주세요 (없으면 빈칸으로 Enter):

라벨 (복수 선택 가능, 쉼표 구분):
  🐞 BugFix | ⚙ Setting | ✅ Test | ✨ Feature | 🌏 Deploy
  🎨 Style  | 📃 Docs   | 🔨 Refactor | 🙋‍♂️ Question | ✏️chore

마일스톤:
  1) v1.0.0 출시

담당자:
  1) joanna930224

위 내용으로 GitHub Issue를 생성할까요? (y/n)
```

---

### STEP 5 — GitHub Issue 생성

사용자가 승인(y)하면 아래 명령을 실행한다:

```bash
gh issue create \
  --title "[이슈 제목]" \
  --body "[생성된 본문]" \
  --label "[선택한 라벨들]" \
  --milestone "[선택한 마일스톤]" \
  --assignee "[선택한 담당자]"
```

- 라벨이 여러 개면 `--label` 플래그를 반복 사용
- 마일스톤/담당자가 없으면 해당 플래그 생략
- 생성 완료 후 이슈 URL을 사용자에게 출력

---

## 규칙

- DESCRIPTION은 반드시 한 문장으로 작성한다
- TO-DO는 반드시 체크박스 형태로 작성한다
- 기능은 논리적으로 그룹핑한다
- 불필요한 설명 없이 바로 사용할 수 있는 형태로 출력한다
- 사용자가 제시한 이슈의 작업 내용이 너무 크거나 많을 경우 여러 이슈로 나눠서 출력한다
- 사용자 승인 없이 절대 GitHub Issue를 생성하지 않는다
