이슈 제목, 번호, 본문을 직접 입력받아 작업 계획 문서를 생성하는 커맨드입니다.

## 사용법

```
/plan [제목] #[이슈번호]

[이슈 설명]

TO-DO
[할일 목록]
```

예시:

```
/plan 기타 코드 데이터를 관리할 로컬 DB 설계 및 구축 #11

기타 코드 데이터를 관리할 로컬 DB를 설계 및 구축한다. ...

TO-DO
- Drift 패키지 도입
- DB 스키마 설계
```

---

## 실행 절차

### STEP 1 — 입력 파싱

`$ARGUMENTS`에서 아래 정보를 추출한다:

- **이슈 번호**: `#숫자` 패턴에서 추출
- **이슈 제목**: `#숫자` 앞의 텍스트
- **이슈 본문**: 첫 줄 이후 전체 내용 (DESCRIPTION + TO-DO 포함)

### STEP 2 — 프로젝트 현황 파악

아래 파일들을 읽고 현재 프로젝트 상태를 파악한다:

1. `CLAUDE.md`
2. `pubspec.yaml`
3. `docs/architecture/` 하위 모든 문서
4. 이슈와 관련된 기존 소스 파일들 (`lib/` 탐색)

### STEP 3 — 작업 계획 MD 생성

`docs/work_plan/plan_[이슈번호].md` 파일을 아래 형식으로 생성한다.
(파일이 이미 존재하면 내용을 보완하여 업데이트한다)

---

## 생성할 파일 형식

```markdown
# Issue #[번호] - [제목]

## 이슈 요약

> [DESCRIPTION 내용 요약]

## 관련 파일

[작업 영향을 받는 파일 목록 - 탐색 결과 기반]

## Phase 구성 원칙

**각 Phase는 반드시 독립적으로 커밋 가능한 상태여야 한다.**

- Phase 완료 시점에 `flutter analyze` 오류 0개
- 미래 Phase에서 구현할 함수·클래스를 참조하는 코드는 해당 Phase에 포함 금지
- 의존성이 생기는 경우, 참조 대상(stub 포함)과 참조 코드를 같은 Phase로 묶는다
- Phase 간 순서는 "컴파일 가능 상태 유지"를 최우선으로 설계한다

## 작업 단계

### Phase 1: [단계명]

**목표:** [이 단계에서 달성할 것]
**작업 파일:**

- `경로/파일명.dart` — [작업 내용]

**완료 조건:**

- [ ] [확인 항목]
- [ ] flutter analyze 오류 없음

**커밋 메시지 제안:** `feat: [내용] (#이슈번호)`

---

### Phase 2: [단계명]

...

## 주의사항

[이슈별 특이사항, 의존성, 주의할 점]

## 작업 시작 전 체크리스트

- [ ] docs/architecture/ 문서 숙지 완료
- [ ] 관련 기존 코드 파악 완료
```

### STEP 4 — 완료 보고

문서 생성이 완료되었음을 사용자에게 알린다.
작업은 여기서 끝이며, 코드 수정은 사용자가 해당 문서를 지목하여 작업을 지시할 때 시작한다.
