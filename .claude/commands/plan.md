이슈 제목, 번호, 본문을 직접 입력받아 작업 계획 문서를 생성하는 커맨드입니다.

## 사용법

```
/plan [제목] #[이슈번호]

[이슈 설명]

TO-DO
[할일 목록]
```

예시:

```
/plan 기타 코드 데이터를 관리할 로컬 DB 설계 및 구축 #11

기타 코드 데이터를 관리할 로컬 DB를 설계 및 구축한다. ...

TO-DO
- Drift 패키지 도입
- DB 스키마 설계
```

---

## 실행 절차

### STEP 1 — 입력 파싱

`$ARGUMENTS`에서 아래 정보를 추출한다:

- **이슈 번호**: `#숫자` 패턴에서 추출
- **이슈 제목**: `#숫자` 앞의 텍스트
- **이슈 본문**: 첫 줄 이후 전체 내용 (DESCRIPTION + TO-DO 포함)

### STEP 2 — 프로젝트 현황 파악

아래 파일들을 읽고 현재 프로젝트 상태를 파악한다:

1. `CLAUDE.md`
2. `pubspec.yaml`
3. `docs/architecture/` 하위 모든 문서
4. 이슈와 관련된 기존 소스 파일들 (`lib/` 탐색)

### STEP 3 — 작업 계획 MD 생성

`docs/work_plan/plan_[이슈번호].md` 파일을 아래 형식으로 생성한다.
(파일이 이미 존재하면 내용을 보완하여 업데이트한다)

## 생성할 파일 형식

이슈 내용에 따라 아래 섹션을 선택적으로 포함한다.

- **화면 전환·사용자 인터랙션·바텀시트·다이얼로그 등 플로우가 있는 경우** → `## 전체 플로우` 섹션 추가
- **UI 컴포넌트를 새로 구현하거나 레이아웃을 정의해야 하는 경우** → `## UI 상세 명세` 섹션 추가

```markdown
# Issue #[번호] - [제목]

## 이슈 요약

> [DESCRIPTION 내용 요약]

## 전체 플로우
(플로우가 있는 경우에만 포함)

[사용자 인터랙션의 시작부터 끝까지 트리 구조로 작성]
진입점 → 화면/컴포넌트 → 분기 조건 → 결과 순으로 표현.

예:
```
코드 카드 탭
  └─ 저장 선택 바텀시트 오픈
      ├─ "새 Box 생성" 탭
      │    └─ 바텀시트 닫힘 → 생성 다이얼로그 오픈
      │        ├─ 성공 → 토스트
      │        └─ 실패 → 토스트
      └─ "기존 Box에 추가" 탭
           └─ ...
```

## UI 상세 명세
(UI 구현이 있는 경우에만 포함)

각 화면·컴포넌트별로 아래 항목을 구체적으로 기술한다:
- 레이아웃 구조 (상단/하단, 버튼 배치 등)
- 표시되는 데이터 (어떤 값을 어떤 형식으로)
- 상태별 UI 변화 (활성/비활성, 빈 상태, 로딩 등)
- 사용할 아이콘 (Icons.xxx)

## Phase 구성 원칙

**각 Phase는 반드시 독립적으로 커밋 가능한 상태여야 한다.**

- Phase 완료 시점에 `flutter analyze` 오류 0개
- 미래 Phase에서 구현할 함수·클래스를 참조하는 코드는 해당 Phase에 포함 금지
- 의존성이 생기는 경우, 참조 대상(stub 포함)과 참조 코드를 같은 Phase로 묶는다
- Phase 간 순서는 "컴파일 가능 상태 유지"를 최우선으로 설계한다
- **공통 컴포넌트(`shared/template`)는 해당 Phase에서 처음 실제로 사용되는 시점에 함께 구현한다** — 미리 만들어 커밋하지 않는다
```
