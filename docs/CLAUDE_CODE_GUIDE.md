# Claude Code 사용 가이드

## 파일 구조

```
프로젝트 루트/
├── CLAUDE.md                        # Claude 영구 규칙 (매 세션 자동 로드)
├── .claude/
│   └── commands/
│       ├── issue.md                 # /issue 커맨드 정의
│       └── plan.md                  # /plan 커맨드 정의
└── docs/
    ├── architecture/                # 아키텍처 규칙 문서들
    └── work_plan/                   # 이슈별 작업 계획 MD (자동 생성됨)
        ├── plan_11.md
        ├── plan_12.md
        └── ...
```

---

## 세션 시작 방법

### 첫 세션 (프로젝트 처음 파악)

```
이 프로젝트를 파악해줘. 아래 순서로 읽어봐:
1. CLAUDE.md
2. pubspec.yaml
3. lib/ 디렉토리 전체 구조
4. docs/architecture/ 하위 모든 문서

파악 완료 후 아래 내용을 나에게 요약 보고해줘:
- 전체 구조 및 아키텍처 패턴
- 주요 패키지 목록
- 네이밍 및 폴더 구조 규칙
- 파악하면서 확인이 필요한 것

보고 전까지 코드 수정 금지.
```

### 이후 세션 (일반 작업)

Claude Code는 CLAUDE.md를 자동으로 읽으므로 바로 작업 지시 가능.
컨텍스트가 오래됐다 싶으면 `/clear` 후 재시작.

## 이슈 작업 플로우

### 1단계: GitHub 이슈 생성

```
/issue Box 화면 및 보관함 기능

사용자가 저장한 곡을 보관하고 탐색할 수 있는 화면

- 정렬 기능 (최근 저장순, ㄱㄴㄷ/ABC)
- 곡 리스트 UI (스크롤, 리스트 타일)
- 제목 검색 기능
```

Claude가 GitHub 이슈에 붙여넣을 Markdown 텍스트를 생성한다.
→ 내가 직접 GitHub에 이슈를 올리고 **이슈 번호를 확인**한다.

### 2단계: 작업 계획 생성

GitHub에서 이슈 번호를 확인한 후:

```
/plan Box 화면 및 보관함 기능 #12

[이슈 본문 내용 붙여넣기]
```

Claude가 자동으로:
- CLAUDE.md, pubspec.yaml, architecture 문서 읽기
- 관련 기존 소스 파악
- `docs/work_plan/plan_12.md` 작업 계획 생성
- 단계별 계획 보고 + **Phase 1 승인 요청**

진행 승인 전까지 코드 수정 없음.

### 3단계: 계획서 기반 실제 작업 시작

계획서를 검토한 후 Phase 1 진행을 승인할 때:

```
plan_12.md 기준으로 Phase 1 진행해줘.
```

또는 특정 Phase만 지정할 때:

```
plan_12.md 읽고 Phase 2부터 진행해줘.
현재까지 완료된 작업: [완료된 내용 간단히 설명]
```

새 세션에서 이어서 작업할 때:

```
docs/work_plan/plan_12.md 읽고 현재 진행 상황 파악해줘.
Phase 1은 완료됐고, Phase 2부터 진행 예정이야.
```

### 4단계: 단계별 승인 진행

Claude가 Phase 완료 후 멈추면:

```
확인했어, Phase 2 진행해
```

수정이 필요하면:

```
이 부분은 [이유]로 수정해줘. 수정 후 다시 보여줘.
```

### 5단계: 내가 직접 Git 커밋

각 Phase 완료 + 확인 후 내가 직접:

```bash
git add .
git commit -m "feat: [내용] (#12)"
git push
```

## 유용한 커맨드 모음

| 커맨드                       | 설명                                        |
| ---------------------------- | ------------------------------------------- |
| `/issue [제목]`              | GitHub 이슈 본문 Markdown 생성              |
| `/plan [제목] #[이슈번호]`   | 작업 계획 MD 생성 (docs/work_plan/)         |
| `/clear`                     | 컨텍스트 초기화 (새 작업 시작 전 권장)      |
| `/compact`                   | 컨텍스트 요약 압축 (50% 이상 찼을 때)       |
| `/compact [지시]`            | 압축 시 보존할 내용 지정                    |

### /compact 활용 예시

```
/compact 수정된 파일 목록과 현재 진행 중인 Phase를 반드시 보존해줘
```

## 상황별 프롬프트 레퍼런스

### 계획만 먼저 볼 때

```
코드는 수정하지 말고, 작업 계획만 먼저 세워서 보고해줘.
```

### 특정 파일만 파악시킬 때

```
lib/data/local/ 폴더 구조만 파악하고 현재 상태를 요약해줘.
코드 수정은 하지 마.
```

### 오류 디버깅

```
flutter analyze 결과야. 원인 파악하고 수정 계획을 먼저 알려줘:
[오류 내용 붙여넣기]
```

### 단계 되돌리기

```
방금 작업한 내용이 마음에 안 들어. 이전 상태로 되돌리고 다른 방식으로 다시 계획해줘.
```

## 컨텍스트 관리 원칙

- 컨텍스트가 **50%** 이상 차면 `/compact` 실행
- 완전히 새로운 기능 작업 시작 전엔 `/clear`
- 조사 작업은 범위를 좁게 제한 ("이 파일들만 봐줘")
- 긴 문서나 파일은 `@파일경로` 대신 직접 "읽어줘"로 요청

## Git 작업 원칙 (중요)

Claude Code는 절대 Git 작업을 하지 않는다.
모든 커밋과 Push는 내가 직접 수행한다.

```bash
# Phase 완료 후 내가 직접 실행
git add .
git commit -m "feat(issue-11): Drift DB 테이블 정의"
git push origin [브랜치명]
```

커밋 메시지 컨벤션:

```
feat:     새 기능
fix:      버그 수정
refactor: 리팩토링
chore:    설정, 패키지 등
docs:     문서
```
